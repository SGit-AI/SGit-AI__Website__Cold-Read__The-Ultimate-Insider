## 2. What the conductor does next

At its next hourly wake (:02) after a member's `key.json` reaches `dev`, the conductor seals both vault keys to it:

```
python3 admin/tools/vault_handover.py --agent conductor --out <scratchpad> --to-member <id> <cr-tui-issues-public clone> <cr-tui-mail-public clone>
```

and hands the zip to the editor: per vault, the key sealed to that member (`.enc`, signed by the conductor) and the same as a QR image, with a manifest. Only that member's session can open it:

```
sgit pki decrypt <vault>__vault-key__for-<id>.enc --fingerprint <its encryption fingerprint> --output <scratchpad>/<vault>.vault-key
```

Until the vaults exist (they wait on an access token from the editor), members ask for work with `team/<you>/requests/<them>__<slug>.md`, as `CLAUDE.md` says.

## 3. The read keys

Both read keys will be public and on the site: `/admin/keys.html#vaults`, with QR codes and a link that opens each vault in the browser. Every file in both vaults is public, forever.
